# 校园远控 Windows

在两台 64 位 Windows 电脑上打开 CampusRemote.exe，分别选择被控端、控制端。EXE 自带 Python 运行库和编解码组件。软件会在两端独立选择可用的 NVIDIA、Intel 或 AMD 硬件编解码路径，并在需要时回退到 CPU。

## 无外网的局域网

1. 宿舍台式机点击「开始共享」→「设备连接」。选择「局域网」，点「上线等待连接」。
2. 控制端打开「设备连接」并选择「局域网」。首次填写被控端显示的内网 IPv4、固定设备号和固定密码，点击「连接设备」。
3. 连过一次后，在「已保存设备」中选择被控端。IP、设备号和密码会自动填入。被控端也会记住成功连接的控制端。
4. 若网络重新分配了被控端 IPv4，修改已保存设备的地址再连。

局域网模式只用两台设备之间的 TCP 49322 和 TLS 加密，无需公网信令、STUN 或 TURN，不需要路由器端口转发。两台电脑必须能通过局域网互通。若相互不可达，请检查网络是否隔离客户端，以及 Windows 防火墙是否允许该应用接收入站连接。状态栏会显示「局域网直连」。可使用 IPv4:端口的地址形式；被控端 EXE 默认监听 49322。

## 公网固定设备号与自动部署

1. 被控端点击「开始共享」→「设备连接」→「公网」→「部署 Cloudflare」。执行部署的电脑需安装带 npm 的 Node.js LTS，另一台电脑只需运行 EXE。
2. 在浏览器登录 Cloudflare 并确认授权。若登录下有多个账号，软件会让你选部署目标。没有 workers.dev 子域名时，软件会尝试创建一个。它将部署包内的 Worker，验证 HTTPS 地址后保存，并自动上线等待连接。
3. 在被控端点「复制公网连接码」，私下发给控制端一次。控制端复制收到的码，在「设备连接 → 公网」点击「从剪贴板导入连接码」。软件会自动填写信令地址、设备号、固定密码并发起连接。以后选择「已保存设备」即可重连。
4. 如果已有可用的信令服务，也可以手工填写 HTTPS 地址。信令服务只转交换连接所需的密文。能够直连时显示「P2P 直连」，否则可使用事先配置的 TURN。自动部署只创建信令服务，TURN 仍需要服务商提供的临时凭证。

局域网模式无需 Node.js、Cloudflare 账号或外网。固定密码保存在当前 Windows 用户的 DPAPI 设备档案中。连接码包含固定密码，请只发给允许连接的人。

本版通过了真实 Wrangler 的部署演练与本地 Worker 和 Durable Object 收发验证，应用界面通过了模拟 Cloudflare 授权、创建子域名、部署完成保存及导入连接码测试。正式公网发布仍需你的 Cloudflare 账号完成授权。

## Render 自动部署（备用）

在被控端的「设备连接 → 公网」选择「部署 Render」。在 Render 账号设置创建一个有工作区读取、Web 服务创建权限的 API Key，只把密钥输入软件弹出的密码框。软件不会保存 API Key。它会尝试在选定工作区创建新加坡区域的免费信令服务，加载包内两份信令脚本，并在验证 /health 后保存地址、开始上线。

重复点击会先检查同名服务，避免重复创建。取消等待不会撤销已经提交给 Render 的部署。控制端首次导入新的公网连接码，之后照常从设备列表连接。Render 不提供本项目的 TURN 中继。

已验证本机的 Render 兼容信令程序和自动配对。自动部署的创建、复用及保存流程用模拟 Render API 验证。实际 Render 发布需要有效授权。

## 手动部署公网信令（可选）

进入仓库的 signal 目录。使用自己的 Cloudflare 账号：

    npx wrangler login
    npx wrangler deploy

把部署返回的 HTTPS 地址填进两端。配置使用 SQLite Durable Object、密文短期邮箱，条目约两分钟自动清理。需要用自己的 Cloudflare 账号授权部署。未内置 TURN 账号。纯局域网完全可以跳过这些步骤。

[Cloudflare Wrangler 文档](https://developers.cloudflare.com/workers/wrangler/commands/)

## 测试

- 在本机非回环内网 IPv4 上显式禁用公网信令及 STUN/TURN，验证错误密码被拒、以 TLS 连接并解码 1080p、保存双方记录和选已保存设备重连。
- 用本地 HTTP 夹具运行同一份 Worker 代码，验证固定设备号和密码的自动信令、加密保存和重连。Cloudflare 公网实际部署及两台真实设备的校园网连通性未验证。
- 1080p60 表示原型的目标档位，实际表现受设备性能和网络影响。源码运行需在同目录执行 python -m pip install -r requirements.txt。最终 EXE 可通过 --diagnose-lan REPORT.json 运行同机局域网性能诊断。

- v0.1.0 的 Windows EXE 在本机局域网回环测试中使用 DXGI、NVENC 和 NVDEC，1080p 的 10 次显示帧率采样为 56–60 FPS。尚无两台独立电脑间的测速数据。



键鼠修复：先勾「允许控制键鼠」，再点「开始共享」，授权现在会同步到新建共享会话。本机 P2P 测试验证了鼠标移动、点击和按键消息送达。

## 键鼠焦点

控制端勾选「发送键鼠」后，单击实际远程画面进入键鼠接管。此时普通实体键盘事件（包括 Win 键和常见快捷键）由控制端转发到被控端。鼠标移到黑边、工具栏或窗口外，或者窗口失焦时，程序停止转发并释放远端按键和按钮。返回画面后单击可重新接管。F12 在本机退出接管。Windows 安全组合键不在此范围内。

已用模拟事件验证焦点切换、画面边界、按键释放及 F12。实体键盘端到端验证仍待实机确认。

新版「网络统计」可显示连接方式、应用层往返延迟、接收码率、显示帧率、分辨率和编解码方式。往返延迟包含被控端排队时间，非 ICMP ping。方向键修复及延迟回包需要更新被控端；新控制端也会传递独立方向键和数字小键盘的扩展标志。

## 分辨率和帧率

控制端可选 360p、480p、720p、1080p（1920×1080）、2K（2560×1440）、4K（3840×2160）或者「自定义…」。自定义宽高需为偶数，最小 320×180、单边最多 4096，总像素不超过 4096×2160。它调整输出视频尺寸，比例与源桌面不同时会按所选尺寸缩放画面。

目标帧率为 10、15、24、30、60、120、144、165 或 240 FPS，码率上限最高可选 60 Mbps。高档位的实际显示帧率取决于屏幕采集、编码、网络、解码和控制端显示能力。请看「网络统计」确认实际帧率。


## 从源码运行和打包

在 64 位 Windows 上使用 Python 3.12，从仓库根目录执行：

```powershell
python -m pip install -r requirements.txt
python app.py
```

构建 Windows EXE：

```powershell
python -m pip install pyinstaller==6.22.3
python -m PyInstaller --noconfirm CampusRemote.spec
```

生成的文件位于 `dist/CampusRemote.exe`。
